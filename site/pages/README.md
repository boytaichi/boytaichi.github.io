# prospereum.io — static pages (GitHub Pages layout, sheet v2 row 1)

Plain HTML + ES modules, no bundler, no web fonts, no third-party loads (row 7). Drops into the `prospereum-website` repository as a branch once Fire has read access; until then it lives here and is posted to #prospereum as a zip.

- `token/` — Token page per Token Page Spec v6: `config.js` (the only typed constants: endpoints, addresses, selectors), `token-logic.mjs` (pure: call list, decoding, formats, backlog, epoch window, fixed copy), `token.js` (browser: chainId check, one `eth_blockNumber` per refresh, every getter at that block, 60 s refresh + focus, "Stale — last successful snapshot" on failure, upstream identity from the Worker's `X-Prospereum-Upstream` header), `index.html` (layout; Treasury row = live rounded `balanceOf`, address unlinked; footer sentence verbatim, row 6).
- `index.html` (Overview = Site Copy & IA v1 §2.1 Home + §2.5 "Where you can use it", verbatim; live strip = total supply / emitted / cap / block), `protocol/` (Protocol = §2.3 "How you earn it", verbatim, plus a read-only live block — released, reserve, treasury, split, epoch state, timelocks — through the same constants and decoding as the Token page) and `about/` (About = §2.2 "What PSRE is", verbatim, plus the launch / audit facts; static, no chain read). Added 29 Oct.
- `shared/live-logic.mjs` (pure: `subsetCalls` filters the Token page's call list to the keys a page asks for — never a new selector; `deriveSubset`, `overviewStrip`, `snapshotLine`) and `shared/live.js` (browser glue: same endpoint order, chainId check, one block per refresh, 60 s, stale banner; the page declares `data-live-keys="overview|protocol"`). Tests: `node --test shared/test/live-logic.test.mjs` (4).
- `use/` (**Where you can use it** = Site Copy & IA v1 §2.5, verbatim, plus the IA §1 live datum — PartnerVault count: `activeVaultCount` / `vaultCount` read from the factory at one block through `shared/live.js` with `data-live-keys="use"`; a "Live partners" line rendered by `shared/live.js` from the pinned snapshot's `activeVaultCount` — "—" without a snapshot, the empty state at 0, the count otherwise; never typed (finding 9)). Added 30 Oct — the sixth and last page of the copy.
- `shared/call-manifest.mjs` — the ONE capability manifest (Kin PR #1 finding 2): derives every static (contract, selector) pair from `token/config.js` + `partners/config.js` and the per-vault selectors for dynamic PartnerVault targets; `../worker/src/index.js` imports it for its allowlist, so pages and Worker cannot drift. The manifest also annotates every getter with its **return types** (`RETURN_TYPES`, round 3 finding 1), which `token-logic.mjs` / `partners-logic.mjs` put on each call and `shared/abi.mjs` checks for canonical encoding. `shared/rpc.mjs` — shared JSON-RPC client + endpoint fallback (finding 3): chainId check, then the **whole** pinned-block snapshot per endpoint; a rejected / rate-limited / malformed (incl. a bad response envelope — wrong `jsonrpc`, mismatched `id`, not exactly one of `result`/`error`, round 3 finding 5) / undecodable (non-canonical result, round 3 finding 1) / timed-out read anywhere falls through to the next endpoint. Tests: `node --test shared/test/rpc.test.mjs` (16).
- `shared/chrome.mjs` — the ONE nav + footer definition (six nav entries in order; footer sentence verbatim from sheet v2 row 6). `node scripts/stamp-chrome.mjs` rewrites every page's `<nav>`/`<footer>` from it (`--check` fails on drift). Never edit a page's nav by hand.
- `test/site.test.mjs` — integration: shared chrome on every page, every internal href/src resolves, a local static serve answers 200 for all six pages and headless Chrome loads each with no JavaScript error (network blocked → live blocks degrade to "—", the Use page partner line stays "—"); phone-width nav hit-test (finding 10): the real header in a 390 px / 360 px iframe viewport — six links inside the viewport, no overlap, no horizontal scroll, each the element at its own centre, wrapped onto ≥ 2 rows; one row at 1280 px. Site QA 2026-11-25 additions: one `<h1>` per page and each page's own; canonical / Open Graph / favicon metadata agreeing with title, description and route; `robots.txt` → `sitemap.xml` (six routes) and a branded root-absolute `404.html` (stamped with the shared chrome, no nav entry — `shared/chrome.mjs` `STANDALONE`); US spelling in visible text; the Token page rendered in Chrome against a canonical same-origin `/rpc` stub (return types from the manifest) — every span carrying a key filled, duplicates identical (A1); the Partners page in a 1440 px and a 390 px iframe — contracts-table header cells keep a gap, the address wraps at most once, no horizontal scroll, the empty state in the prose font (R1/R2).
- `site.css` — shared styles. `favicon.svg`, `robots.txt`, `sitemap.xml` (six routes on `https://prospereum.io`), `404.html` (GitHub Pages serves it for unknown paths; `noindex`, root-absolute links) — added after the site QA of 2026-11-25.
- `scripts/copy-drift.mjs` (+ `test/copy-drift.test.mjs`) — **copy drift**: every sentence of Site Copy & IA v1 §2.1 (Home), §2.2 (About), §2.3 (Protocol) and §2.5 (Use, and its echo on Home) must appear verbatim on its page; 69 sentences checked. Deliberate deviations live in `scripts/copy-drift.allow.json` with the reason (four: the Home live strip is read from the chain, not typed; `partnerships@` is unpublished on Home and Use per Decision Sheet v2 row 6 — the pages point to Partners & Developers; About says "decentralized", US spelling). The Token page (§2.4) and Partners page (§2.6) are governed by the later accepted baselines — Token Page Spec v6 and SDK Spec v4 — and are not diffed against v1 copy. A stale allow entry fails the check.
- `scripts/build-zip.mjs [name]` — **release candidate**: chrome `--check` → all page tests (22) → copy drift → Worker tests (11) → `../dist/<name>.zip` (pages/ + worker/ + DEPLOY.md + RELEASE.txt) with `<name>.zip.sha256`. `../DEPLOY.md` is the one-page deploy + verify note for Kin/Jason.

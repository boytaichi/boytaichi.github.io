## 2. RPC Worker (`worker/`, sheet row 2) — the only thing with a secret

- Cloudflare Worker `prospereum-rpc`, `wrangler.toml` as shipped. Routes `prospereum.io/rpc` **and** `prospereum.io/rpc/*` on the site zone (the second serves the health probe), or a dedicated `rpc.prospereum.io` — pick one; the pages try `/rpc` first and fall through to the public endpoints in Token Page Spec v6 §6 order. Fallback covers the **whole** pinned-block snapshot: a rejected, rate-limited, malformed, **undecodable** or timed-out read anywhere in a refresh moves the page to the next endpoint (Kin PR #1 finding 3); the page's timeout covers the response body, not only the headers (round 2 finding 9). *Undecodable* means not the **canonical ABI encoding of the getter's declared return types** (round 2 finding 2, round 3 finding 1): every getter is annotated with its return type(s) in `pages/shared/call-manifest.mjs` `RETURN_TYPES` (bool, address, uint256, uint24 for the pool `fee()`, `(uint256,uint256)` for the four pending getters, `address[]` for `getAllVaults()`), and `pages/shared/abi.mjs` accepts a result only when a bool word is 0 or 1, an address word has zero high bytes, a uintN fits its width, a static return has exactly one word per type, and an `address[]` has offset 0x20, a length word and exactly that many clean address words with no trailing data. *Malformed* includes the response envelope (round 3 finding 5): the browser, like the Worker, requires `jsonrpc` `"2.0"`, the `id` it sent, exactly one of `result`/`error`, and an error of `{ integer code, string message }`. A snapshot is never shown with a partial number: "—" only when every endpoint failed.
- **Allowlist = the pages' own call manifest** (`pages/shared/call-manifest.mjs`, derived from `token/config.js` and `partners/config.js`; the Worker imports it, wrangler bundles it). Adding a getter to a page config admits it in the Worker in the same commit. Each selector is annotated with its argument word count and the Worker admits calldata of **exactly** 4 + 32·n bytes (balanceOf / vaultActive: 36; every other page getter: 4) — trailing bytes are rejected, direct or inside a Multicall (round 2 finding 5). Dynamic PartnerVault targets are admitted for the four per-vault selectors only after the Worker reads `factory.vaultActive(vault)` upstream at the same pinned block; verdicts are cached 60 s, bounded, and keyed by **(vault, block)** so a vault decommissioned between blocks is never admitted from a stale verdict (round 2 finding 1). `worker/test/manifest.integration.test.mjs` replays every page call through the Worker (Kin finding 2).
- **Secret, server-side only:** `wrangler secret put UPSTREAM_URL` — the keyed Base-mainnet RPC URL (Alchemy free tier or equivalent). It never appears in `wrangler.toml`, the pages, the repository, a log or an error: upstream failures answer fixed public messages (`upstream unavailable` / `upstream returned an invalid response`), upstream JSON-RPC errors are reduced to `execution reverted` / `upstream rpc error`, and only validated results are cached (Kin finding 7). The upstream envelope is validated — `jsonrpc` `"2.0"`, response `id` equal to the id the Worker sent, exactly one of `result`/`error`, error `{ integer code, string message }` — and a mismatch is a 502 that is never cached (round 2 finding 7); the request envelope must carry `"jsonrpc":"2.0"` too. The page shows only `UPSTREAM_NAME`.
- Vars (in `wrangler.toml`): `SITE_ORIGIN=https://prospereum.io` (exact origin: CORS allow-origin **and** the required `Origin` of every `POST /rpc` — an originless or foreign-origin POST is 403, round 2 finding 6; `GET …/rpc/health` stays originless; change it if the site is previewed on another origin), `UPSTREAM_NAME` (display string), `CACHE_TTL_SECONDS=60` (1–3600). Rate-limit binding `RATE_LIMITER`: 60 requests / 10 s per IP — **mandatory**; without it (or with any of the four bindings missing/malformed) every request answers `503 {"error":"service misconfigured"}` (Kin finding 6). `DEV_ALLOW_NO_RATE_LIMIT="true"` is for local `wrangler dev` / the preview gate only.
- Limits (Kin finding 4): request body ≤ 64 KiB counted in **bytes** — `Content-Length` is checked before any read, then the body stream is read with a byte counter and cut off past the limit (round 2 finding 8); direct calldata ≤ 260 bytes (and exactly the selector's length, above); Multicall3 calldata ≤ 32 KiB with ≤ 64 inner calls of ≤ 260 bytes each; EIP-1898 `requireCanonical` rejected (finding 8); in-isolate cache bounded to 1,024 entries (LRU), keyed by a SHA-256 of the normalised params.
- Verify before pointing the pages at it: `node --test test/*.test.mjs` from `worker/` (35 tests, no install), then `GET https://<worker-host>/rpc/health` → `200 {"ok":true,…}` (checks the bindings and runs one allowed + one rejected call shape without touching the upstream), one live `eth_call` of `totalSupply()` through the route → 200, and one disallowed selector → **HTTP 400 with JSON-RPC error -32602** (finding 11: the allowlist rejection is 400, not 403; 403 is reserved for a missing or foreign `Origin`). `node scripts/verify-deploy.mjs https://prospereum.io --rpc https://<worker-host>/rpc --pinned-block 0x<recent block>` from `pages/` runs all of these, including the originless-POST 403 and the allowed call at the pinned block.

### Preview gate (round 2 finding 3) — what CI proves, and what it cannot

CI cannot deploy to Cloudflare: there is no API token in the repository's secrets, and the Pages project's output directory is Jason's A3 item. So the pre-merge gate serves the **exact checkout** itself. `.github/workflows/pr-checks.yml` job `preview` runs `node scripts/preview-gate.mjs` from `pages/` twice:

1. `--worker shim` (offline, deterministic): `scripts/serve.mjs` serves `site/pages` from the checkout; `worker/scripts/stub-upstream.mjs` plays a Base node (fixed block `0x3276f9f`, echoes JSON-RPC ids); `worker/scripts/dev-shim.mjs` runs the Worker's exported `handle()` behind a Node HTTP server with `SITE_ORIGIN` = the served origin and `DEV_ALLOW_NO_RATE_LIMIT`.
2. `--worker wrangler`: the same pages and stub, with the real Worker under `npx wrangler@3 dev --local` (workerd; `[[unsafe.bindings]]` rate limiter stubbed by miniflare, so `/rpc/health` reports `rateLimiter:true`). npx fetches wrangler — the only network use; no deploy, no token.

Each run executes `scripts/verify-deploy.mjs <origin> --rpc <worker>/rpc --pinned-block 0x3276f9f --exact .`: six routes 200 with the shared nav/footer and same-origin scripts; `GET /rpc` 405, `GET /rpc/health` 200 ok, disallowed method 4xx, disallowed selector 400/-32602, originless POST 403, **one allowed call** (`PSRE.totalSupply()` at the pinned block) 200 with a word-aligned result and the `X-Prospereum-Upstream` header; and **every published file and directory route served byte-identical to the checkout** (`--exact`; 19 files, 25 URLs). The gate also asserts the stub upstream saw the allowed call and never a disallowed one. Any mismatch fails the job — a stale artifact on the served routes fails `--exact` (3 checks per stale page).

Limitations, stated plainly: the shim exercises `handle()` under Node, not workerd — routes, the production rate-limit binding, `cf-connecting-ip` and isolate lifecycle are only approximated (the wrangler run covers workerd locally, still not the production zone). Neither run touches Base: the upstream is a stub, so decoded figures are the stub's. The deployed-origin checks (§4) remain the release proof; the preview gate proves the artifact and the Worker contract before merge. Locally: `node scripts/preview-gate.mjs --worker shim` from `pages/` runs in ~2 s with no install.
